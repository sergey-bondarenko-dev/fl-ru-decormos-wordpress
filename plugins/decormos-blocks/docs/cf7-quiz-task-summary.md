# CF7 Quiz Task Summary

## Задача

Сделать простой пошаговый квиз для WordPress/Gutenberg на базе Contact Form 7.

Основные условия:

- без подсчета результатов;
- без калькулятора стоимости;
- ответы уходят одной обычной заявкой CF7;
- форма выглядит как пошаговый квиз;
- шаг 2 зависит от шага 1: блоки площади показываются только для выбранных поверхностей.

## Файлы

- `plugins/decormos-blocks/docs/cf7-quiz-template.html` — шаблон разметки для вставки в CF7.
- `plugins/decormos-blocks/src/scripts/modules/cf7-quiz.js` — фронтовая логика шагов, условных блоков и валидации.
- `plugins/decormos-blocks/src/scripts/frontend.js` — подключает `initCf7Quiz()`.
- `plugins/decormos-blocks/src/styles/components/cf7-quiz.scss` — временные стили для наглядности.
- `plugins/decormos-blocks/src/styles/frontend.scss` — подключает стили квиза.
- `plugins/decormos-blocks/inc/cf7.php` — серверная условная валидация CF7-квиза.
- `docker-compose.yml` и `var/wp-content/mu-plugins/mailpit.php` — локальная проверка писем через Mailpit.

## Как использовать

1. В админке WordPress открыть нужную форму Contact Form 7 или создать новую.
2. Вставить содержимое `plugins/decormos-blocks/docs/cf7-quiz-template.html` в тело формы.
3. Настроить шаблон письма CF7.
4. Вставить форму на страницу через существующий Gutenberg-блок CF7 или шорткод Contact Form 7.
5. Убедиться, что на странице подключается frontend-бандл плагина `decormos-blocks`.

## Критичные маркеры разметки

Форма должна иметь корневой маркер:

```html
<div class="cf7-quiz" data-cf7-quiz>
```

Для включения серверной валидации именно этого квиза нужен hidden-маркер:

```text
[hidden decormos_cf7_quiz "1"]
```

Шаги должны иметь:

```html
<div class="cf7-quiz__step" data-cf7-quiz-step>
```

Кнопки навигации:

```html
data-cf7-quiz-next
data-cf7-quiz-prev
```

В шаблоне можно использовать плейсхолдер:

```text
{{privacy_policy_url}}
```

При рендере формы он заменяется на результат стандартной WordPress-функции `get_privacy_policy_url()`.

## Связь шага 1 и шага 2

На шаге 1 поле `surface` содержит обычные значения CF7:

```text
"Стены" "Пол" "Потолок" "Лестница" "Мебель" "Ваш вариант"
```

На шаге 2 каждый условный блок связан с одним из этих значений через `data-cf7-quiz-area`:

```html
<div class="cf7-quiz__area" data-cf7-quiz-area="Стены" hidden>
```

Если добавить новый вариант в `surface`, нужно синхронно обновить:

- вариант в `[checkbox* surface ...]`;
- блок на шаге 2 с таким же `data-cf7-quiz-area`;
- PHP-карту `$area_fields_by_surface` в `plugins/decormos-blocks/inc/cf7.php`;
- шаблон письма CF7, если новое поле должно попадать в письмо.

## Ограничение выбора на шаге 1

Максимальное количество выбранных поверхностей задается data-атрибутом:

```html
<div data-cf7-quiz-max-checked="3">
```

JS отключает остальные чекбоксы, когда лимит достигнут. Серверная валидация в `inc/cf7.php` также проверяет максимум 3 значения для `surface`.

Если поменять число, нужно синхронно обновить:

- `data-cf7-quiz-max-checked`;
- сообщение/текст подсказки в шаблоне;
- серверную проверку `count( $surface_values ) > 3` в `inc/cf7.php`.

## Валидация

### Фронт

`cf7-quiz.js` валидирует текущий видимый шаг перед переходом дальше:

- видимые `checkbox`/`radio`-группы должны иметь выбранный вариант;
- видимые текстовые поля должны быть заполнены;
- скрытые блоки не валидируются;
- при ошибке шаг не переключается и показывается сообщение.

Также JS:

- показывает на шаге 2 только блоки, выбранные на шаге 1;
- очищает значения скрытых блоков;
- ставит `disabled` на поля скрытых area-блоков, чтобы они не попадали в отправку.

### Сервер

CF7 radio-поля валидируются сервером жестко, даже если соответствующий блок был скрыт на фронте. Поэтому для квиза добавлена своя серверная валидация в `inc/cf7.php`.

Она срабатывает только для форм с:

```text
[hidden decormos_cf7_quiz "1"]
```

Логика:

- стандартный результат CF7-валидации сбрасывается только для этой квиз-формы;
- `surface` обязателен;
- `surface` не больше 3 значений;
- area-поле обязательно только если выбрана соответствующая поверхность;
- `timing`, `phone`, `contact_method` обязательны.

Это MVP-решение. Оно хрупкое, потому что PHP-валидация привязана к именам полей и русским значениям `surface`.

## Почему radio оставлены на шаге 2

Для площади нужно выбрать один вариант, поэтому на шаге 2 используются `radio`, а не `checkbox`.

Важно: обычная серверная CF7-валидация плохо подходит для условно скрытых radio-полей. Поэтому обязательность этих полей контролируется нашей JS/PHP-логикой.

## Шаблон письма CF7

Готовый шаблон лежит в:

```text
plugins/decormos-blocks/docs/cf7-quiz-mail-template.txt
```

Его можно перенести в настройки вкладки `Почта` у формы CF7.

Пример:

```text
Новая заявка на расчет покрытия

Контакты
Телефон: [phone]
Предпочтительный способ связи: [contact_method]

Задача
Поверхности: [surface]
Сроки: [timing]

Площадь / объем работ
Площадь стен: [walls_area]
Площадь пола: [floor_area]
Площадь потолка: [ceiling_area]
Лестница: [stairs_area]
Мебель: [furniture_area]
Другое: [other_surface_area]

Техническая информация
Страница: [_url]
Дата отправки: [_date] [_time]
IP: [_remote_ip]
```

Поля площади на шаге 2 сейчас отправляются через hidden-поля `walls_area`, `floor_area`, `ceiling_area`, `stairs_area`, `furniture_area`. Видимые кастомные radio/number элементы только заполняют эти hidden-поля через JS.

## Локальная проверка писем

Добавлен Mailpit:

- web UI: `http://localhost:8025`;
- SMTP внутри Docker-сети: `mailpit:1025`.

MU-plugin `var/wp-content/mu-plugins/mailpit.php` в `local` окружении направляет `wp_mail()` в Mailpit.

После изменения `docker-compose.yml` нужно пересоздать/поднять контейнеры:

```bash
docker compose up -d
```

## Сборка и проверки

После изменений JS/SCSS запускать:

```bash
npm run build
```

Для PHP:

```bash
php -l plugins/decormos-blocks/inc/cf7.php
php -l var/wp-content/mu-plugins/mailpit.php
```

Ожидаемые предупреждения сборки: Sass deprecation warnings и предупреждения о больших webp-ассетах. Они не связаны с квизом.

## Чеклист после правок

- Шаг 1 не пускает дальше без выбора поверхности.
- На шаге 1 нельзя выбрать больше 3 поверхностей.
- Шаг 2 показывает только блоки выбранных поверхностей.
- Если вернуться на шаг 1 и снять поверхность, ее площадь очищается.
- Шаг 2 не пускает дальше без площади для каждого видимого блока.
- Шаг 3 не пускает дальше без срока.
- Финальный шаг не отправляет форму без телефона и способа связи.
- CF7 submit не возвращает ошибки по скрытым area-полям.
- Письмо приходит в Mailpit.
